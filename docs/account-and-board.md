# アカウントとボードのデータの扱い

## 用語

| 用語           | 意味                                                                                 |
| -------------- | ------------------------------------------------------------------------------------ |
| アカウント     | DID で識別される ATProto の主体。Linkat を使っているかは問わない                     |
| ハンドル       | アカウントの今の名前。変わることがあり、他のアカウントに移ることもある               |
| プロフィール   | 表示名・アバター・説明                                                               |
| ボードの持ち主 | `blue.linkat.board/self` を持つアカウント。Linkat 以外のクライアントで書いた人も含む |
| 編集者         | Linkat にログインしているアカウント。ボードはまだ無くてもよい                        |
| 閲覧者         | ボードのページを開いている人。ログインしていなくてもよい                             |

「ユーザー」という言葉は使わない。

## 正しい値の持ち主

| データ               | 正しい値の持ち主                                                   | 変更の通知              |
| -------------------- | ------------------------------------------------------------------ | ----------------------- |
| DID                  | ATProto(変わらない)                                                | —                       |
| ハンドル             | ATProto(DID ドキュメントと、DNS または `.well-known` の双方向検証) | Jetstream の `identity` |
| プロフィール         | 本人の PDS の `app.bsky.actor.profile/self`                        | Jetstream の commit     |
| アカウントの状態     | PDS とリレー                                                       | Jetstream の `account`  |
| ボード               | 本人の PDS の `blue.linkat.board/self`                             | Jetstream の commit     |
| OAuth セッション     | Linkat                                                             | —                       |
| Jetstream のカーソル | Linkat                                                             | —                       |

- Linkat が持ち主のドメインデータは無い。DB のボード・プロフィール・ハンドル・状態は、すべて外部の値の写しである
- アバターは blob の CID を持ち、表示用の URL は Bluesky の CDN の形式(`https://cdn.bsky.app/img/avatar/plain/{did}/{cid}@jpeg`)で組み立てる

## ルール

Linkat が決めて守るルールは次の2つだけで、強い集約は置かない。

1. パスのハンドルは、必ず ATProto で解決する(双方向の検証つき)。DB の写しでハンドルから DID を決めない
2. 写しの中でハンドルを重複させない。検証済みのハンドルを書き込むときは、同じトランザクションで同じハンドルを持つ他の行を null にしてから書く。ユニーク制約(null は可)で保証する

次は不変条件ではない。

- ボードがあれば持ち主のプロフィールの写しがある。写しが無いときは、DID とハンドルだけで表示する。そのため外部キーは張らない
- 編集者の写しがある。編集者はセッションの DID だけで成り立つ

## 写しの範囲

- 写しを持つのはボードの持ち主だけ。閲覧やログインでは写しの行を作らない
- テーブルは `Board` と持ち主の写しに分け、外部キーは張らない
- 持ち主の写しは DID・ハンドル・`handleVerifiedAt`・表示名・説明・アバター CID・状態を持つ
- ボードの写しが削除されたら、持ち主の写しも削除する

## 鮮度

| 写し             | 更新の手段                                                                      | 古さの許容                  | 失敗したとき                                |
| ---------------- | ------------------------------------------------------------------------------- | --------------------------- | ------------------------------------------- |
| ボード           | `/edit` の POST の直後と Jetstream                                              | Jetstream の遅れまで        | —                                           |
| ハンドル         | Jetstream、検証済みの値の書き戻し、`handleVerifiedAt` から1時間を過ぎたら再解決 | 1時間                       | 上書きせず、`handleVerifiedAt` も更新しない |
| プロフィール     | Jetstream                                                                       | 次の変更イベントまで        | 初回は空のまま。更新時は既存の値を残す      |
| アカウントの状態 | Jetstream                                                                       | 次の `account` イベントまで | —                                           |

- Jetstream の取りこぼしは許容する
- DID から解決して `handle.invalid` になったときは上書きしない
- Jetstream の `identity` を受けたら、その DID の解決のキャッシュを捨てる

## 表示

`/$handle` と `/edit` は、同じ「持ち主の表示用データを読む」処理を使う。

1. 行き先を決める
   - `/$handle` のパスがハンドルなら、毎回 DID に解決する。存在しない場合や検証に失敗した場合は 404、一時的な障害なら 503 にする
   - `/edit` はセッションの DID を使う
2. DID でボードと持ち主の写しを読む。停止・削除・無効化されたアカウントなら 404 にする
3. ハンドルを最新に保つ
   - 手順1で得た検証済みのハンドルが写しと違えば書き戻す
   - `handleVerifiedAt` から1時間を過ぎていれば、DID から解決し直して書き戻す
4. 表示と URL には写しのハンドルを使う。null なら DID を使う
5. 写しが無いとき、`/$handle` はボードが無いので 404 にする。`/edit` はハンドルとプロフィールをその場で取得して表示し、保存はしない

## 出来事ごとの変化

| 出来事                                                       | ボードの写し | プロフィールの写し                   | ハンドルの写し                                                    | 状態の写し          |
| ------------------------------------------------------------ | ------------ | ------------------------------------ | ----------------------------------------------------------------- | ------------------- |
| ログインした                                                 | 変えない     | 変えない                             | 変えない                                                          | 変えない            |
| ボードを公開・更新した(`/edit` の POST、Jetstream の commit) | upsert       | 行が無ければ PDS から取得して作る    | 行が無ければ解決して入れる                                        | 行が無ければ active |
| ボードが削除された(Jetstream、`/delete`)                     | 削除         | 行ごと削除                           | 行ごと削除                                                        | 行ごと削除          |
| ハンドルが変わった(`identity`)                               | 変えない     | 変えない                             | 行があれば更新する                                                | 変えない            |
| プロフィールが変わった(profile の commit)                    | 変えない     | 行があれば更新する                   | 変えない                                                          | 変えない            |
| 停止・削除・無効化・復帰(`account`)                          | 残す         | 残す                                 | 残す                                                              | 行があれば記録する  |
| `/$handle` が閲覧された                                      | 読むだけ     | 読むだけ                             | 検証済みのハンドルが違えば書き戻す。1時間を過ぎていれば解決し直す | 読むだけ            |
| `/$did` が閲覧された                                         | 読むだけ     | 読むだけ                             | 1時間を過ぎていれば解決し直す                                     | 読むだけ            |
| `/edit` を開いた                                             | 読むだけ     | 写しを読む。無ければその場で取得する | 1時間を過ぎていれば解決し直す。行が無ければその場で解決する       | —                   |

ハンドルの写しを書き込むときは、常にルール2に従う。
