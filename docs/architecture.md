# アーキテクチャ

## 構成

### サーバーの層

| 層       | 場所                                        | 役割                                                            |
| -------- | ------------------------------------------- | --------------------------------------------------------------- |
| 入口     | `app/routes`、`app/server/service/ingester` | リクエストや外部のイベントを受け取り、サービスを呼ぶ            |
| サービス | `app/server/service`                        | 出来事ごとの処理と、表示用データの読み取りを行う                |
| インフラ | `app/server/infrastructure`                 | DBや外部サービスとのやり取りを行い、外部の値をDTOに変換して返す |

サービスとインフラは`{層}/{関心}/ファイル`の形で置く。DTOは`{関心}/{関心}Dto.ts`(例: `owner/ownerDto.ts`)に置き、型名は`{名前}Dto`にする。

依存の組み立ては`app/server/di.ts`で行う。

### ディレクトリ

| 場所             | 役割                                                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `app/routes`     | 入口。loader・actionでサービスを呼び、ページに値を渡す                                                   |
| `app/pages`      | 画面1枚分のUI                                                                                            |
| `app/features`   | 機能ごとのUI部品とhook                                                                                   |
| `app/components` | 機能に依存しないUI部品                                                                                   |
| `app/hooks`      | 機能に依存しないhook                                                                                     |
| `app/schemas`    | レコードの値を検証するzodスキーマ。lexiconで表せない制約を補う                                           |
| `app/generated`  | lexiconから生成したコード                                                                                |
| `app/i18n`       | 翻訳                                                                                                     |
| `app/libs`       | 外部ライブラリの拡張                                                                                     |
| `app/utils`      | 汎用の小さな関数                                                                                         |
| `app/mocks`      | テスト用のmsw                                                                                            |
| `app/server`     | サーバーだけで動くコード。`app/pages`・`app/features`・`app/components`からは`import type`でだけ参照する |

## 方針

### 集約とドメインイベントを置かない

DBにあるデータは、すべて外部の値の写しである。Linkatが守る不変条件は`docs/spec.md`のルールだけで、トランザクションで守る集約は無い。そのため、強い集約、ドメインイベントの型、イベントバスは置かない。

### 出来事ごとに処理を1つにまとめる

`docs/spec.md`の「出来事ごとの変化」の1行を、サービスの1つの処理にする。同じ出来事が複数の入口(編集画面、Jetstreamなど)から起きるときも、同じ処理を呼ぶ。入口は判断を持たず、受け取った値を出来事に変えてサービスを呼ぶだけにする。仕様で決まった分岐(同期済みかどうか、PDSとDBのどちらで失敗したかなど)はサービスが持ち、入口が画面の出し分けに使う結果は例外ではなく戻り値で返す。

### 外部の値は境界で変換する

ATProto・PDS・Jetstreamから受け取った値は、インフラと入口でLinkatの言葉に変換し、サービスへは外部の形のまま渡さない。例えば、`handle.invalid`はnullに変え、解決の失敗は理由を区別せずnullで返す。

サービスはPDSなどの外部のクライアントを受け取らず、DIDなどのLinkatの値だけを受け取る。クライアントの組み立てはインフラで行う。

### 写しのハンドルは1つの処理で書き込む

`docs/spec.md`のルール2は、リポジトリの1つの書き込み処理で守る。写しのハンドルを書き込む処理は、すべてそれを通す。
