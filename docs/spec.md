# アカウントとボードのデータの扱い

## 用語

| 用語           | コード中の名前 | 意味                                                                               |
| -------------- | -------------- | ---------------------------------------------------------------------------------- |
| アカウント     | `account`      | DIDで識別されるATProtoの主体。Linkatを使っているかは問わない                       |
| ハンドル       | `handle`       | アカウントの今の名前。変わることがあり、他のアカウントに移ることもある             |
| プロフィール   | `profile`      | 表示名・アバター・説明                                                             |
| ボードの持ち主 | `owner`        | `blue.linkat.board/self`を持つアカウント。Linkat以外のクライアントで書いた人も含む |
| 編集者         | `editor`       | Linkatにログインしているアカウント。ボードはまだ無くてもよい                       |
| 閲覧者         | `viewer`       | ボードのページを開いている人。ログインしていなくてもよい                           |

「ユーザー」という言葉は使わない。

## 正しい値の持ち主

| データ              | 正しい値の持ち主                                                       | 変更の通知            |
| ------------------- | ---------------------------------------------------------------------- | --------------------- |
| DID                 | ATProto。値は変わらない                                                | なし                  |
| ハンドル            | ATProto。DIDドキュメントと、DNSまたは`.well-known`の双方向検証で決まる | Jetstreamの`identity` |
| プロフィール        | 本人のPDSの`app.bsky.actor.profile/self`                               | Jetstreamのcommit     |
| アカウントの状態    | PDSとリレー                                                            | Jetstreamの`account`  |
| ボード              | 本人のPDSの`blue.linkat.board/self`                                    | Jetstreamのcommit     |
| OAuthセッション     | Linkat                                                                 | なし                  |
| Jetstreamのカーソル | Linkat                                                                 | なし                  |

Linkatが正しい値の持ち主になっているドメインデータは無い。DBにあるボード・プロフィール・ハンドル・状態は、すべて外部の値の写しである。

アバターはblobのCIDで持つ。表示用のURLは、BlueskyのCDNの形式`https://cdn.bsky.app/img/avatar/plain/{did}/{cid}@jpeg`で組み立てる。

## ルール

Linkatが決めて守るルールは次の3つだけで、強い集約は置かない。

1. ハンドルの解決(DNS・HTTP・DIDドキュメントによる双方向の検証)は、写しへの書き込みの処理の中でだけ行う。それ以外の場面では、ハンドルとDIDの対応をDBの写しから引く
2. 写しの中でハンドルを重複させない。検証済みのハンドルを書き込むときは、同じトランザクションの中で、同じハンドルを持つ他の行を先にnullにする。重複が無いことは、nullを許すユニーク制約で保証する
3. 写しへの書き込みは、Jetstreamと編集者の操作(`/edit`のPOST、`/delete`)だけが行う。それ以外の場面では写しを読むだけにする

ログインのときのハンドルの解決はOAuthの仕組みに含まれるので、ルール1の例外とする。

一方で、次の2つは不変条件にしない。

1つ目は「ボードがあれば、持ち主のプロフィールの写しもある」という条件である。写しが無いときは、DIDだけで表示する。そのため外部キーは張らない。

2つ目は「編集者の写しがある」という条件である。編集者はセッションのDIDだけで成り立つ。

## 写しの範囲

写しを持つのはボードの持ち主だけで、閲覧やログインでは写しの行を作らない。テーブルは`Board`と持ち主の写しの`Owner`に分け、外部キーは張らない。

持ち主の写しには、DID・ハンドル・表示名・説明・アバターのCID・状態を入れる。ボードの写しが削除されたら、持ち主の写しも削除する。

Jetstreamではすべてのアカウントのプロフィールと`identity`・`account`のイベントが届く。持ち主の写しが無いアカウントのイベントは捨てる。

## 鮮度

| 写し             | 更新の手段                                         | 古さの許容                                     | 失敗したとき                           |
| ---------------- | -------------------------------------------------- | ---------------------------------------------- | -------------------------------------- |
| ボード           | `/edit`のPOSTとJetstream                           | Jetstreamの遅れまで                            | -                                      |
| ハンドル         | `/edit`のPOSTとJetstreamの書き込みのたびに解決する | 次の`identity`・プロフィール・ボードの変更まで | nullにする                             |
| プロフィール     | `/edit`のPOSTとJetstream                           | 次の変更イベントまで                           | 初回は空のまま。更新時は既存の値を残す |
| アカウントの状態 | Jetstream                                          | 次の`account`イベントまで                      | -                                      |

Jetstreamの取りこぼしは許容する。そのため、写しのハンドルが今のハンドルとずれることがある。DIDから解決した結果が`handle.invalid`だったり、双方向の検証に失敗したりしたときは、写しのハンドルをnullにする。解決の失敗と一時的な障害は区別しない。

## 表示

`/$handle`と`/edit`は、同じ「持ち主の表示用データを読む」処理を使う。

`/$handle`のパスがハンドルなら、最初にDBの写しからDIDを引き、以降はDIDだけで処理する。写しに無いハンドルは404にする。`account`イベントで`active`がfalseだったアカウントは、ボードの代わりに表示できない旨と`status`の値を表示する。OG画像は404にする。

表示とURLには写しのハンドルを使う。写しのハンドルがnullならDIDを使う。

`/edit`で写しが無いときは、DIDで表示し、プロフィールはその場でPDSから取得する。どちらも保存はしない。

## 出来事ごとの変化

| 出来事                                                   | ボードの写し | 持ち主の写し                                                                                      |
| -------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------- |
| ボードを公開・更新した(`/edit`のPOST、Jetstreamのcommit) | upsert       | プロフィールをPDSから取得し、ハンドルを解決してupsertする。状態は行が無ければ`active`をtrueにする |
| ボードが削除された(Jetstream、`/delete`)                 | 削除         | 削除                                                                                              |
| プロフィールが変わった(profileのcommit)                  | 変えない     | 行があれば、レコードの値で更新し、ハンドルを解決し直す                                            |
| ハンドルが変わった(`identity`)                           | 変えない     | 行があれば、ハンドルを解決し直す                                                                  |
| 停止・削除・無効化・復帰(`account`)                      | 残す         | 行があれば、`active`と`status`をそのまま記録する                                                  |
| ログインした、`/$handle`・`/$did`・`/edit`を開いた       | 読むだけ     | 読むだけ                                                                                          |

ハンドルの写しを書き込むときは、常にルール2に従う。
