# アカウントとボードのデータの扱い

## 用語

| 用語           | 意味                                                                               | コード中の名前 |
| -------------- | ---------------------------------------------------------------------------------- | -------------- |
| アカウント     | DIDで識別されるATProtoの主体。Linkatを使っているかは問わない                       | `account`      |
| ハンドル       | アカウントの今の名前。変わることがあり、他のアカウントに移ることもある             | `handle`       |
| プロフィール   | 表示名・アバター・説明                                                             | `profile`      |
| ボードの持ち主 | `blue.linkat.board/self`を持つアカウント。Linkat以外のクライアントで書いた人も含む | `owner`        |
| 編集者         | Linkatにログインしているアカウント。ボードはまだ無くてもよい                       | `editor`       |
| 閲覧者         | ボードのページを開いている人。ログインしていなくてもよい                           | `viewer`       |

「ユーザー」という言葉は使わない。

## 正しい値の持ち主

| データ              | 正しい値の持ち主                                                       | 変更の通知            |
| ------------------- | ---------------------------------------------------------------------- | --------------------- |
| DID                 | ATProto。値は変わらない                                                | なし                  |
| ハンドル            | ATProto。DIDドキュメントと、DNSまたは`.well-known`の双方向検証で決まる | Jetstreamの`identity` | `handle`  |
| プロフィール        | 本人のPDSの`app.bsky.actor.profile/self`                               | Jetstreamのcommit     | `profile` |
| アカウントの状態    | PDSとリレー                                                            | Jetstreamの`account`  |
| ボード              | 本人のPDSの`blue.linkat.board/self`                                    | Jetstreamのcommit     |
| OAuthセッション     | Linkat                                                                 | なし                  |
| Jetstreamのカーソル | Linkat                                                                 | なし                  |

Linkatが正しい値の持ち主になっているドメインデータは無い。DBにあるボード・プロフィール・ハンドル・状態は、すべて外部の値の写しである。

アバターはblobのCIDで持つ。表示用のURLは、BlueskyのCDNの形式`https://cdn.bsky.app/img/avatar/plain/{did}/{cid}@jpeg`で組み立てる。

## ルール

Linkatが決めて守るルールは次の2つだけで、強い集約は置かない。

1. パスのハンドルは、必ずATProtoで双方向に検証して解決する。DBの写しを使ってハンドルからDIDを決めることはしない
2. 写しの中でハンドルを重複させない。検証済みのハンドルを書き込むときは、同じトランザクションの中で、同じハンドルを持つ他の行を先にnullにする。重複が無いことは、nullを許すユニーク制約で保証する

一方で、次の2つは不変条件にしない。

1つ目は「ボードがあれば、持ち主のプロフィールの写しもある」という条件である。写しが無いときは、DIDとハンドルだけで表示する。そのため外部キーは張らない。

2つ目は「編集者の写しがある」という条件である。編集者はセッションのDIDだけで成り立つ。

## 写しの範囲

写しを持つのはボードの持ち主だけで、閲覧やログインでは写しの行を作らない。テーブルは`Board`と持ち主の写しに分け、外部キーは張らない。

持ち主の写しには、DID・ハンドル・`handleVerifiedAt`・表示名・説明・アバターのCID・状態を入れる。ボードの写しが削除されたら、持ち主の写しも削除する。

## 鮮度

| 写し             | 更新の手段                                                                         | 古さの許容                | 失敗したとき                               |
| ---------------- | ---------------------------------------------------------------------------------- | ------------------------- | ------------------------------------------ |
| ボード           | `/edit`のPOSTの直後とJetstream                                                     | Jetstreamの遅れまで       | -                                          |
| ハンドル         | Jetstream、検証済みの値の書き戻し、`handleVerifiedAt`から1時間を過ぎたときの再解決 | 1時間                     | 上書きせず、`handleVerifiedAt`も更新しない | `handle`  |
| プロフィール     | Jetstream                                                                          | 次の変更イベントまで      | 初回は空のまま。更新時は既存の値を残す     | `profile` |
| アカウントの状態 | Jetstream                                                                          | 次の`account`イベントまで | -                                          |

Jetstreamの取りこぼしは許容する。DIDから解決した結果が`handle.invalid`だったときは、ハンドルの写しを上書きしない。Jetstreamの`identity`を受けたら、そのDIDの解決結果のキャッシュを捨てる。

## 表示

`/$handle`と`/edit`は、同じ「持ち主の表示用データを読む」処理を使う。

`/$handle`のパスがハンドルなら、毎回DIDに解決する。ハンドルが存在しない場合や検証に失敗した場合は404、一時的な障害なら503にする。停止・削除・無効化されたアカウントのボードも404にする。

表示とURLには写しのハンドルを使う。写しのハンドルがnullならDIDを使う。

`/edit`で写しが無いときは、ハンドルとプロフィールをその場で取得して表示し、保存はしない。

## 出来事ごとの変化

| 出来事                                                   | ボードの写し | プロフィールの写し                   | ハンドルの写し                                                    | 状態の写し         |
| -------------------------------------------------------- | ------------ | ------------------------------------ | ----------------------------------------------------------------- | ------------------ |
| ログインした                                             | 変えない     | 変えない                             | 変えない                                                          | 変えない           |
| ボードを公開・更新した(`/edit`のPOST、Jetstreamのcommit) | upsert       | 行が無ければPDSから取得して作る      | 行が無ければ解決して入れる                                        | 行が無ければactive |
| ボードが削除された(Jetstream、`/delete`)                 | 削除         | 行ごと削除                           | 行ごと削除                                                        | 行ごと削除         |
| ハンドルが変わった(`identity`)                           | 変えない     | 変えない                             | 行があれば更新する                                                | 変えない           |
| プロフィールが変わった(profileのcommit)                  | 変えない     | 行があれば更新する                   | 変えない                                                          | 変えない           |
| 停止・削除・無効化・復帰(`account`)                      | 残す         | 残す                                 | 残す                                                              | 行があれば記録する |
| `/$handle`が閲覧された                                   | 読むだけ     | 読むだけ                             | 検証済みのハンドルが違えば書き戻す。1時間を過ぎていれば解決し直す | 読むだけ           |
| `/$did`が閲覧された                                      | 読むだけ     | 読むだけ                             | 1時間を過ぎていれば解決し直す                                     | 読むだけ           |
| `/edit`を開いた                                          | 読むだけ     | 写しを読む。無ければその場で取得する | 1時間を過ぎていれば解決し直す。行が無ければその場で解決する       | -                  |

ハンドルの写しを書き込むときは、常にルール2に従う。
