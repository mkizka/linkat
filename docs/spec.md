# アカウントとボードのデータの扱い

## 用語

| 用語           | コード中の名前 | 意味                                                                               |
| -------------- | -------------- | ---------------------------------------------------------------------------------- |
| アカウント     | `account`      | DIDで識別されるATProtoの主体。Linkatを使っているかは問わない                       |
| ハンドル       | `handle`       | アカウントの今の名前。変わることがあり、他のアカウントに移ることもある             |
| プロフィール   | `profile`      | 表示名・アバター・説明                                                             |
| ボードの持ち主 | `owner`        | `blue.linkat.board/self`を持つアカウント。Linkat以外のクライアントで書いた人も含む |
| 編集者         | `editor`       | Linkatにログインしているアカウント。ボードはまだ無くてもよい                       |
| 閲覧者         | `viewer`       | ボードのページを開いている人。ログインしていなくてもよい                           |
| 同期           | `sync`         | 編集者の写しを、PDSの今の値で上書きして揃えること                                  |

「ユーザー」という言葉は使わない。

## 正しい値の持ち主

| データ              | 正しい値の持ち主                                                       | 変更の通知            |
| ------------------- | ---------------------------------------------------------------------- | --------------------- |
| DID                 | ATProto。値は変わらない                                                | なし                  |
| ハンドル            | ATProto。DIDドキュメントと、DNSまたは`.well-known`の双方向検証で決まる | Jetstreamの`identity` |
| プロフィール        | 本人のPDSの`app.bsky.actor.profile/self`                               | Jetstreamのcommit     |
| アカウントの状態    | PDSとリレー                                                            | Jetstreamの`account`  |
| ボード              | 本人のPDSの`blue.linkat.board/self`                                    | Jetstreamのcommit     |
| OAuthセッション     | Linkat                                                                 | なし                  |
| Jetstreamのカーソル | Linkat                                                                 | なし                  |

Linkatが正しい値の持ち主になっているドメインデータは無い。DBにあるボード・プロフィール・ハンドル・状態は、すべて外部の値の写しである。

アバターはblobのCIDで持つ。表示用のURLは、BlueskyのCDNの形式`https://cdn.bsky.app/img/avatar/plain/{did}/{cid}@jpeg`で組み立てる。

## 写し

写しを持つのは、ボードの持ち主と、同期した編集者である。閲覧やログインでは写しの行を作らない。

テーブルは`Board`と持ち主の写しの`Owner`に分け、外部キーは張らない。編集者の写しも`Owner`に入れる。持ち主の写しには、DID・ハンドル・表示名・説明・アバターのCID・状態を入れる。ボードの写しが削除されたら、持ち主の写しも削除する。

次の2つは不変条件にしない。

- 「ボードがあれば、持ち主のプロフィールの写しもある」。写しが無いときは、DIDだけで表示する。そのため外部キーは張らない
- 「編集者の写しがある」。編集者はセッションのDIDだけで成り立つ

## ルール

Linkatが決めて守るルールは次の3つだけで、強い集約は置かない。

1. ハンドルの解決(DNS・HTTP・DIDドキュメントによる双方向の検証)は、写しへの書き込みの処理の中でだけ行う。それ以外の場面では、ハンドルとDIDの対応をDBの写しから引く。ログインのときの解決はOAuthの仕組みに含まれるので、例外とする
2. 写しの中でハンドルを重複させない。検証済みのハンドルを書き込むときは、同じトランザクションの中で、同じハンドルを持つ他の行を先にnullにする。重複が無いことは、nullを許すユニーク制約で保証する
3. 写しへの書き込みは、次の節に挙げた入口だけが行う。それ以外の場面では写しを読むだけにする

## 書き込みの入口

写しへの書き込みは、基本的にJetstreamで行う。編集者の操作のうち、次の3つだけを例外にする。

| 入口          | 書くもの                   | 例外にする理由                                                                          |
| ------------- | -------------------------- | --------------------------------------------------------------------------------------- |
| Jetstream     | すべての写し               | 基本の入口                                                                              |
| `/edit`のPOST | ボードの写し               | 保存した結果をすぐ表示するため                                                          |
| `/delete`     | ボードと持ち主の写しの削除 | 削除した結果をすぐ表示するため                                                          |
| `/sync`のPOST | 持ち主とボードの写し       | Jetstreamには接続した後の変化しか届かないので、編集者が使い始めた時点の値を取り込むため |

Jetstreamにはすべてのアカウントのイベントが届くが、持ち主の写しが無いアカウントのイベントは捨てる。

`/edit`のPOSTで持ち主の写しを書かないのは、同じ書き込みがJetstreamのcommitとして届き、そこで更新されるためである。

同期は、編集者の写しをPDSの今の値で上書きする。プロフィールをPDSから取得し、ハンドルを解決して、持ち主の写しをupsertする。ボードはPDSにあれば写しをupsertし、無ければ作らない。何度呼んでも、その時点のPDSの値に揃う。

`/sync`は、`/edit`を開いてボードの写しが無かったときに画面から呼ぶ。ハンドルの解決とPDSからの取得は時間がかかるので、画面の表示を待たせないためにloaderの中では行わない。

## 出来事ごとの変化

| 出来事                                             | ボードの写し                        | 持ち主の写し                                                                                      |
| -------------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------- |
| ボードを公開・更新した(Jetstreamのcommit)          | upsert                              | プロフィールをPDSから取得し、ハンドルを解決してupsertする。状態は行が無ければ`active`をtrueにする |
| 編集者がボードを保存した(`/edit`のPOST)            | upsert                              | 変えない                                                                                          |
| 編集者が同期した(`/sync`のPOST)                    | PDSにあればupsert。無ければ作らない | プロフィールをPDSから取得し、ハンドルを解決してupsertする。状態は行が無ければ`active`をtrueにする |
| ボードが削除された(Jetstream、`/delete`)           | 削除                                | 削除                                                                                              |
| プロフィールが変わった(profileのcommit)            | 変えない                            | 行があれば、レコードの値で更新し、ハンドルを解決し直す                                            |
| ハンドルが変わった(`identity`)                     | 変えない                            | 行があれば、ハンドルを解決し直す                                                                  |
| 停止・削除・無効化・復帰(`account`)                | 残す                                | 行があれば、`active`と`status`をそのまま記録する                                                  |
| ログインした、`/$handle`・`/$did`・`/edit`を開いた | 読むだけ                            | 読むだけ                                                                                          |

ハンドルの写しを書き込むときは、常にルール2に従う。

## 鮮度

| 写し             | 古さの許容                                     | 失敗したとき                           |
| ---------------- | ---------------------------------------------- | -------------------------------------- |
| ボード           | Jetstreamの遅れまで                            | -                                      |
| ハンドル         | 次の`identity`・プロフィール・ボードの変更まで | nullにする                             |
| プロフィール     | 次の変更イベントまで                           | 初回は空のまま。更新時は既存の値を残す |
| アカウントの状態 | 次の`account`イベントまで                      | -                                      |

Jetstreamの取りこぼしは許容する。そのため、写しのハンドルが今のハンドルとずれることがある。DIDから解決した結果が`handle.invalid`だったり、双方向の検証に失敗したりしたときは、写しのハンドルをnullにする。解決の失敗と一時的な障害は区別しない。

## 表示

`/$handle`と`/edit`は、同じ「持ち主の表示用データを読む」処理を使う。

`/$handle`のパスがハンドルなら、最初にDBの写しからDIDを引き、以降はDIDだけで処理する。写しに無いハンドルは404にする。ボードの写しが無いときも404にする。`account`イベントで`active`がfalseだったアカウントは、ボードの代わりに表示できない旨と`status`の値を表示する。OG画像は404にする。

表示とURLには写しのハンドルを使う。写しのハンドルがnullならDIDを使う。

`/edit`を開いたときも写しを読むだけにする。ボードの写しが無ければ`/sync`を呼び、終わったら読み直す。同期が終わるまでは編集させない。PDSにあるボードを空のボードで上書きしないためである。同期に失敗したときは、再試行できるようにする。
