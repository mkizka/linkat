# アカウントとボードのデータの扱い

## 用語

| 用語           | コード中の名前 | 意味                                                                               |
| -------------- | -------------- | ---------------------------------------------------------------------------------- |
| アカウント     | `account`      | DIDで識別されるATProtoの主体。Linkatを使っているかは問わない                       |
| ハンドル       | `handle`       | アカウントの今の名前。変わることがあり、他のアカウントに移ることもある             |
| プロフィール   | `profile`      | 表示名・アバター・説明                                                             |
| ボード         | `board`        | `blue.linkat.board/self`のレコード。カードの並びを持つ                             |
| カード         | `card`         | ボードの1項目。URL・テキスト・絵文字を持つ                                         |
| ボードの持ち主 | `owner`        | `blue.linkat.board/self`を持つアカウント。Linkat以外のクライアントで書いた人も含む |
| 編集者         | `editor`       | Linkatにログインしているアカウント。ボードはまだ無くてもよい                       |
| 閲覧者         | `viewer`       | ボードのページを開いている人。ログインしていなくてもよい                           |
| 同期           | `sync`         | 編集者の写しを、PDSの今の値で上書きして揃えること                                  |

「ユーザー」という言葉は使わない。

## 正しい値の持ち主

| データ              | 正しい値の持ち主                                                       | 変更の通知            |
| ------------------- | ---------------------------------------------------------------------- | --------------------- |
| DID                 | ATProto。値は変わらない                                                | なし                  |
| ハンドル            | ATProto。DIDドキュメントと、DNSまたは`.well-known`の双方向検証で決まる | Jetstreamの`identity` |
| プロフィール        | 本人のPDSの`app.bsky.actor.profile/self`                               | Jetstreamのcommit     |
| アカウントの状態    | PDSとリレー                                                            | Jetstreamの`account`  |
| ボード              | 本人のPDSの`blue.linkat.board/self`                                    | Jetstreamのcommit     |
| OAuthセッション     | Linkat                                                                 | なし                  |
| Jetstreamのカーソル | Linkat                                                                 | なし                  |
| 非表示レベル        | Linkat                                                                 | なし                  |

- Linkatが正しい値の持ち主になっているドメインデータは非表示レベルだけ。DBのボード・プロフィール・ハンドル・状態は、すべて外部の値の写し
- 非表示レベルは、`ADMIN_DIDS`に含まれる管理者が`/moderation`のPOSTで設定する。`Moderation`テーブルにDIDごとに持ち、持ち主の写しが消えても残す
- アバターはblobのCIDで持ち、表示用のURLは`https://cdn.bsky.app/img/avatar/plain/{did}/{cid}@jpeg`(BlueskyのCDNの形式)で組み立てる

| 非表示レベル | 意味                                                             |
| ------------ | ---------------------------------------------------------------- |
| `none`       | 通常どおり表示する                                               |
| `unlisted`   | みんなのリンク集に出さない。ボードのページは表示する             |
| `hidden`     | `unlisted`に加え、ボードのページとOG画像も停止中と同じ扱いにする |

## 写し

| テーブル | 中身                                             | 行を持つアカウント                                   |
| -------- | ------------------------------------------------ | ---------------------------------------------------- |
| `Board`  | ボードの写し                                     | ボードの持ち主                                       |
| `Owner`  | DID・ハンドル・表示名・説明・アバターのCID・状態 | ボードを持ったことがあるアカウントと、同期した編集者 |

- 2つのテーブルの間に外部キーは張らない
- ボードの写しが削除されても、持ち主の写しは残す。ボードを作っていない編集者と同じ扱いになる

lexiconの検証に通らないボードのレコードは写しにせず、理由を警告ログに残す。通ったレコードでも、次をすべて満たすカードだけを写しに入れる。満たさないカードは捨て、残りのカードで写しを作る。入口によらず同じ検証を使う。

- URLかテキストの少なくとも一方が空でない
- URLは空か、`http://`または`https://`で始まる
- 絵文字は空か、絵文字1文字だけ

このルールは、lexiconで表せない制約を補うものである。Linkat以外のクライアントで書いたカードでも、満たさないものは写しに入らず、編集者がLinkatで保存したときにPDSからも消える。

次の2つは不変条件にしない。

| 不変条件にしないもの                             | 写しが無いとき   |
| ------------------------------------------------ | ---------------- |
| ボードがあれば、持ち主のプロフィールの写しもある | DIDだけで扱う    |
| 編集者の写しがある                               | トップで同期する |

## ルール

Linkatが決めて守るルールは次の3つだけで、強い集約は置かない。

1. ハンドルの解決(DNS・HTTP・DIDドキュメントによる双方向の検証)は、写しへの書き込みの中でだけ行う
   - それ以外では、ハンドルとDIDの対応をDBの写しから引く
   - ログインのときの解決はOAuthの仕組みに含まれるので例外
2. 写しの中でハンドルを重複させない
   - 検証済みのハンドルを書き込むときは、同じトランザクションで、同じハンドルを持つ他の行を先にnullにする
   - nullを許すユニーク制約で保証する
3. 写しへの書き込みは、次の節の入口だけが行う。それ以外では写しを読むだけ

## 書き込みの入口

写しへの書き込みは、基本的にJetstreamで行う。編集者の操作のうち、以下を例外にする。

| 入口          | 書くもの             | 例外にする理由                                                                          |
| ------------- | -------------------- | --------------------------------------------------------------------------------------- |
| Jetstream     | すべての写し         | 基本の入口                                                                              |
| `/edit`のPOST | ボードの写し         | 保存した結果をすぐ表示するため                                                          |
| `/delete`     | ボードの写しの削除   | 削除した結果をすぐ表示するため                                                          |
| `/sync`のPOST | 持ち主とボードの写し | Jetstreamには接続した後の変化しか届かないので、編集者が使い始めた時点の値を取り込むため |

- Jetstreamにはすべてのアカウントのイベントが届くが、持ち主の写しが無いアカウントのイベントは捨てる
- ハンドルの解決とPDSからの取得は時間がかかるので、loaderでは行わず、画面から`/sync`を呼ぶ

## 出来事ごとの変化

| 出来事                                    | ボードの写し                                          | 持ち主の写し                                                                                           |
| ----------------------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| ボードを公開・更新した(Jetstreamのcommit) | upsert                                                | プロフィールをPDSから取得し、ハンドルを解決してupsertする。状態は行が無ければ`active`をtrueにする      |
| 編集者がボードを保存した(`/edit`のPOST)   | upsert                                                | 変えない                                                                                               |
| 編集者が同期した(`/sync`のPOST)           | PDSにあればupsert。無ければ作らない                   | プロフィールをPDSから取得し、ハンドルを解決してupsertする。状態は行が無ければ`active`をtrueにする      |
| ボードが削除された(Jetstream、`/delete`)  | 削除                                                  | 変えない                                                                                               |
| プロフィールが変わった(profileのcommit)   | 変えない                                              | 行があれば、レコードの値で更新し、ハンドルを解決し直す。レコードが削除されたら、プロフィールを空にする |
| ハンドルが変わった(`identity`)            | 変えない                                              | 行があれば、ハンドルを解決し直す                                                                       |
| 停止・削除・無効化・復帰(`account`)       | 残す                                                  | 行があれば、`active`と`status`をそのまま記録する                                                       |
| リポジトリが同期し直された(`sync`)        | 持ち主の写しがあれば、PDSにあればupsert。無ければ削除 | 行があれば、プロフィールをPDSから取得し、ハンドルを解決してupsertする                                  |
| ログイン、その他ページの閲覧              | 読むだけ                                              | 読むだけ                                                                                               |

## 鮮度

| 写し             | 古さの許容                                     | 失敗したとき                                                                       |
| ---------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| ボード           | Jetstreamの遅れまで                            | -                                                                                  |
| ハンドル         | 次の`identity`・プロフィール・ボードの変更まで | nullにする                                                                         |
| プロフィール     | 次の変更イベントまで                           | 初回は空のまま。更新時は既存の値を残す。レコードが無いときは失敗ではなく、空にする |
| アカウントの状態 | 次の`account`イベントまで                      | -                                                                                  |

- Jetstreamの取りこぼしは許容する。そのため写しのハンドルが今のハンドルとずれることがある
- ハンドルの解決の失敗には、`handle.invalid`、双方向の検証の失敗、一時的な障害のすべてを含む

## 表示

- `/$handle`のパスがハンドルなら、最初にDBの写しからDIDを引き、以降はDIDだけで処理する
- URLには写しのハンドルを使う。nullならDIDを使う
- 表示には写しのハンドルを使う。nullか写しが無ければ「無効なハンドル」と表示する。OG画像では「@handle.invalid」にする

### `/$handle`の表示

| 状態                                           | 表示                                                                    |
| ---------------------------------------------- | ----------------------------------------------------------------------- |
| 写しに無いハンドル                             | 404                                                                     |
| `account`イベントで`active`がfalse             | ボードの写しの有無に関わらず、表示できない旨と`status`の値。OG画像は404 |
| 非表示レベルが`hidden`(管理者と持ち主本人以外) | 表示できない旨だけ。OG画像は404                                         |
| ボードの写しが無い                             | 404                                                                     |

### ログイン中で写しが無いとき

| 画面                             | 写し         | 動き                                                                     | 同期に失敗したとき                                         |
| -------------------------------- | ------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| トップ                           | 持ち主の写し | `/sync`を呼び、終わるまで同期画面を出す                                  | 再試行画面は出さず、「無効なハンドル」と初期アバターで表示 |
| `/edit`(POSTを含む)・`/settings` | 持ち主の写し | トップにリダイレクトし、トップでもう一度同期する                         | -                                                          |
| `/edit`                          | ボードの写し | `/sync`を呼び、終わるまで編集させない(PDSのボードを空で上書きしないため) | 再試行できるようにする                                     |
